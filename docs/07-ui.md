# 07 UI

## Principles

1. **One primary screen per mode.** Anonymous: the date-grouped list. Signed in: the Inbox. Everything else is a
   tab away, never a modal maze.
2. **Dense but calm.** Event rows show title, time, venue, category chip, price, score. Images are optional and
   small in lists, large on detail. Text first; this is a programme, not a poster wall.
3. **Keyboard and thumb.** On desktop `j/k` move, `i` interested, `x` skip, `m` maybe, `enter` opens. On mobile the
   same actions are swipe left/right plus a bottom sheet.
4. **Show the why.** Every score has a one-line reason visible without a click. Trust in the AI comes from legible
   reasons, not from the number.
5. **Dates the Berlin way.** `Fr 10.10. · 20:00`, week starts Monday, "heute / morgen / Wochenende" groupings;
   English UI with German date conventions is fine for this audience.
6. **Light and dark**, system-following. Neutral palette, one accent, category colours only as small chips.
7. **No dead ends.** Empty inbox says what the sources are doing and when the next run is.

## Screens (MVP)

| Screen | Route | Content |
| --- | --- | --- |
| Public list | `/` | Sticky filter bar (date range chips, category, district, search). Groups by day. Row click → detail. "Sign in for your picks" quiet banner. |
| Event detail | `/e/:slug` | Title, occurrences list (next 5 + expand), venue card with map link, performers, price, links, AI summary, "sources" footnote, similar events. Signed in: score + reasons + action bar. |
| Inbox | `/inbox` | Ranked cards (score, reasons, quick actions). Filter: this week / all upcoming. Progress "12 of 40". |
| Agenda | `/agenda` | Interested/maybe occurrences by day; conflict badge; iCal subscribe button. |
| Profile | `/me` | Taste text (textarea with examples), toggles, Spotify connect, private sources, API keys. |
| Admin: sources | `/admin/sources` | Table with status, last run, counts, run-now; drawer for config (JSON editor with schema validation). |
| Admin: review | `/admin/review` | Side-by-side extracted vs. existing; approve / merge / reject. |
| Admin: usage | `/admin/usage` | Today's free-tier counters as bars; Claude spend; last 24 h runs. |
| Add | `/add` (and a `+` button everywhere) | Tabs: photo (camera on mobile), text, URL. Shows extraction result for confirmation. |

## Reference sites to study (and to point a design tool at)

| Site | Why it is a good reference | What to borrow |
| --- | --- | --- |
| **Resident Advisor** – ra.co/events/de/berlin | The canonical dense, date-grouped event list; strong typographic hierarchy; dark theme done well | Day headers, row layout (time · title · venue · lineup), filter bar behaviour |
| **Rausgegangen** (ex Ask Helmut) – rausgegangen.de/en, Berlin section | Berlin-native discovery with mood/radius filters and curated "today" view | Filter chips, "today / weekend" entry points, how they handle multi-date shows |
| **DICE** – dice.fm | Mobile-first, image-forward cards, "for you" tab, saved/going states | Card anatomy, action states, the personal tab |
| **Luma** – lu.ma/berlin | Minimal, generous whitespace, calendar subscription as a first-class action | Event detail layout, "add to calendar" flow, calendar-subscribe button |
| **Berlin Bühnen** – berlin-buehnen.de/en/schedule | The theatre Spielplan reference; shows how to present one production with many dates | Occurrence lists per production, stage/venue filters |
| **Songkick / Bandsintown** | Artist-tracking model; "your artists" feeds | Performer-centric matching UI, "because you follow X" explanations |
| **Letterboxd** | Rating/watchlist UX on a dense catalogue | Interested/maybe/went states, personal notes, ratings |
| **Readwise Reader / Feedly** | Inbox-triage UX with keyboard shortcuts | The Inbox screen: ranked queue, j/k, archive/keep |
| **Linear** | Density, keyboard-first, calm visual language | Overall tone, filter popovers, command palette (`cmd+k` for search) |

Avoid as references: Eventbrite and Facebook Events (noisy, ad-driven, poor density).

## Brief for a design tool (paste-ready)

> Design a clean, text-first event discovery web app for Berlin called "BLN Vorstellungen". Two modes: a public
> date-grouped list of events (like Resident Advisor's Berlin listing but lighter, with category chips and a
> district filter) and a signed-in "Inbox" of AI-ranked events, each card showing a 0–100 score with one short
> reason line and quick actions interested / maybe / skip. Include an event detail page (production with multiple
> performance dates, venue card, performers, price, links, AI summary, "sources" footnote), an agenda view, a
> profile page with a free-text taste description and toggles, and an "Add" flow where a user photographs a poster
> and confirms the extracted event. Neutral palette, one accent colour, light and dark themes, mobile-first,
> keyboard shortcuts on desktop. Stack: React, Tailwind, shadcn/ui components. Berlin date format (`Fr 10.10. ·
> 20:00`).
